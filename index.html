How I work

Own the problem.
Follow it through.

I work as a product owner who writes code. The metric sets the direction; the stack follows.

idea ↗ build ↗ learn

Start with what should change.

+

I list the goal and tasks, set priorities, then look for the highest-impact work within the most important problems. Dependencies and production risks shape the order.

02

Go where the problem goes.

+

Sometimes that means a better React interface. Sometimes it means a NestJS API, a data pipeline, or a new way to transcode video. I work across those boundaries.
